Phanthom - Sherlock

Fecha: 01 oct 2026 Dificultad: Medium Categoría: DFIR Sistema: Linux Plataforma: HackTheBox

Resumen

Investigación forense de un volcado de memoria de un servidor Ubuntu Linux 24.04 infectado por un LKM rootkit avanzado llamado singularity. Mediante el uso de Volatility 3, se analizan módulos ocultos, trazas del kernel (ftrace y tracepoints), conexiones de red ocultas y mecanismos de escalada de privilegios mediante variables de entorno.

Escenario

El servidor ha sido comprometido y se cuenta con un volcado de memoria (dump_srv.mem) junto con su archivo de símbolos JSON para el kernel de Ubuntu (6.8.0-87-generic). El objetivo es desenterrar las capacidades del rootkit, identificar las funciones interceptadas y reconstruir el vector de ataque y exfiltración.

Artefactos y herramientas

  • Artefactos: Volcado de memoria dump_srv.mem, archivo de símbolos JSON del kernel Ubuntu_6.8.0-87-generic.json.
  • Herramientas: Volatility 3 (plugins específicos de Linux: linux.hidden_modules, linux.kmsg.Kmsg, linux.tracing.tracepoints, linux.sockstat.Sockstat, linux.tracing.ftrace, linux.envars.Envars).

Análisis

Tarea 1

Pregunta: What is the name of the hidden kernel module?

Verificamos la versión del kernel y utilizamos el plugin de Volatility para listar los módulos del kernel ocultos o desvinculados.

vol -f dump_srv.mem banners
vol -f dump_srv.mem -s . linux.hidden_modules

Respuesta: singularity

Tarea 2

Pregunta: What kernel taint flags are set for the rootkit module? (comma-separated, alphabetical order)

A partir de la información del módulo oculto devuelta por el análisis, identificamos las banderas de taint asociadas al módulo cargado externamente y sin firmar.

Respuesta: OOT_MODULE,UNSIGNED_MODULE

Tarea 3

Pregunta: At what exact time (in seconds since boot) was the rootkit module loaded

Consultamos el registro de mensajes del kernel (kmsg) filtrando por el nombre del rootkit para obtener la marca temporal exacta de su carga.

vol -f dump_srv.mem -s . linux.kmsg.Kmsg | grep -i -B2 -A2 singularity

Respuesta: 2490.473832

Tarea 4

Pregunta: What was the PID of the process that loaded the rootkit module?

Identificamos el PID del proceso responsable de realizar la carga del módulo rootkit en el sistema.

Respuesta: 2669

Tarea 5

Pregunta: Which kernel tracepoint is hooked by the rootkit?

Revisamos los puntos de traza (tracepoints) del kernel para detectar qué mecanismo está siendo interceptado por el módulo.

vol -f dump_srv.mem -s . linux.tracing.tracepoints.CheckTracepoints

Respuesta: sched_process_fork

Tarea 6

Pregunta: What is the IP address of the command and control server?

Analizamos las conexiones de red activas mediante el plugin sockstat para identificar comunicaciones hacia servidores externos de comando y control (C2).

vol -f dump_srv.mem -s . linux.sockstat.Sockstat

Respuesta: 192.168.200.164

Tarea 7

Pregunta: What port is the C2 server listening on?

A partir de la inspección de los sockets establecidos por los procesos comprometidos, determinamos el puerto remoto del servidor C2.

Respuesta: 8081

Tarea 8

Pregunta: What are the PIDs of the compromised bash processes connected to the C2 server? (comma-separated, ascending order)

Listamos y ordenamos de forma ascendente los identificadores de proceso (PIDs) de las instancias de bash involucradas en la conexión con el servidor C2.

Respuesta: 2693,2695,2698

Tarea 9

Pregunta: How many hooks has the rootkit installed?

Utilizamos el subsistema ftrace para buscar todas las referencias al módulo y contar la cantidad total de ganchos instalados en el kernel.

vol -f dump_srv.mem -s . linux.tracing.ftrace.CheckFtrace | grep -i "singularity" | wc -l

Respuesta: 82

Tarea 10

Pregunta: Which function is hooked to hide IPv4 network connections?

Identificamos la función específica del stack de red de Linux modificada para ocultar las conexiones de red IPv4.

Respuesta: tcp4_seq_show

Tarea 11

Pregunta: How many variants of getdents syscalls are hooked?

Examinamos las llamadas al sistema asociadas a la enumeración de directorios (como getdents y su variante moderna getdents64).

Respuesta: 5

Tarea 12

Pregunta: Which function is hooked to enable an ICMP-based covert channel?

Investigamos las funciones encargadas de procesar tráfico ICMP de entrada para descubrir el mecanismo de canal encubierto (covert channel).

Respuesta: icmp_rcv

Tarea 13

Pregunta: What is the memory address of the centralized callback function? (Format:0x****)

Localizamos la dirección de memoria de la función de retrollamada (callback) centralizada utilizada por los mecanismos internos del rootkit.

Respuesta: 0xffffc0b3aac0

Tarea 14

Pregunta: What is the value of the suspicious environment variable which leads to the escalation of privileges?

Analizamos las variables de entorno del sistema y el comportamiento de las sesiones. El operador abre una subshell con una variable personalizada y envía una señal en tiempo real (señal 59) a su propio proceso. Al recibirla, el módulo valida la variable de entorno y modifica la estructura de credenciales para otorgar UID 0 (root).

vol -f dump_srv.mem -s . linux.envars.Envars

Respuesta: access

Indicadores de compromiso (IOC)

  • Módulo Oculto: singularity (Taints: OOT_MODULE, UNSIGNED_MODULE)
  • Servidor C2: 192.168.200.164:8081
  • Variable de Entorno de Escalada: OPERATOR=access
  • PIDs Comprometidos: 2669 (cargador), 2693, 2695, 2698 (conexiones C2)
  • Funciones Clave Enganchadas: sched_process_fork, tcp4_seq_show, icmp_rcv

Conclusiones

Este análisis forense demuestra la complejidad de los rootkits LKM modernos en entornos Linux. A través de Volatility 3, logramos destapar los 82 ganchos instalados por singularity, rastrear el canal encubierto ICMP, las conexiones de red ocultas y descubrir el mecanismo de escalada de privilegios basado en la variable de entorno access y señales en tiempo real.
