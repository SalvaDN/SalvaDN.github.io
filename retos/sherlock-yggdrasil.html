Yggdrasil - Sherlock

Fecha: 07 abr 2026 Dificultad: Hard Categoría: DFIR Sistema: Linux Plataforma: HackTheBox

Resumen

Investigación forense integral de una intrusión en una máquina Ubuntu asignada al equipo de desarrollo. Se reconstruye la cadena de ataque completa: desde el acceso inicial a través de un binario camuflado en un proyecto, la posterior explotación de un servicio vulnerable (telnetd) para obtener privilegios de root, el empaquetado y exfiltración de información sensible, hasta la implementación de persistencia sigilosa.

Escenario

Se detectó una conexión saliente no autorizada en un servidor Ubuntu del equipo de desarrollo, lo que motivó su aislamiento inmediato para triaje. Nuestro objetivo como analistas DFIR es determinar el vector de entrada, los artefactos ejecutados, el alcance de la brecha y los mecanismos de persistencia introducidos por el atacante.

Artefactos y herramientas

  • Artefactos: Registros del sistema (auth.log, kmsg), base de datos Tracker3 (meta.db), bodyfile.txt, historiales de comandos (bash_history) e informes de la herramienta UAC (Unix-Like Artifact Collector).
  • Herramientas: Visores de bases de datos SQLite, análisis de líneas temporales (bodyfiles), utilidades de red y herramientas de triaje forense en Linux.

Análisis

Tarea 1

Pregunta: What is the PID of the malicious process that granted the attacker access to the system?

A través de la revisión inicial de los registros de procesos y conexiones, identificamos el PID del proceso malicioso inicial.

Respuesta: 5241

Tarea 2

Pregunta: What is the full path of the previous malicious process on the system?

Localizamos la ruta exacta desde donde se lanzó el binario o script que dio acceso al atacante dentro de la estructura del proyecto del usuario.

Respuesta: /home/irek/Documents/mcp-connector-hub/vendor/bin/.cache/update

Tarea 3

Pregunta: What is the IP address and port number to which the attacker connected?

Revisando los artefactos de red (como los volcados de conexiones lsof), extraemos la dirección IP externa y el puerto de destino del servidor de comando y control (C2).

Respuesta: 172.168.40.101:1337

Tarea 4

Pregunta: After gaining initial access, the attacker discovered a network daemon running on the system that allowed him to obtain root access. What is the name of the vulnerable service or daemon that enabled the attacker to gain a root shell?

Analizando el historial de comandos de bash y los procesos en ejecución (ps_auxwww.txt), detectamos el servicio de red local aprovechado para la escalada.

Respuesta: telnetd

Tarea 5

Pregunta: We need to collect all IOCs and IOAs so we can perform threat hunting to understand the breach radius. What is the full path of the malicious script file the attacker executed?

Examinando el árbol de directorios y los rastros de ejecución del exploit, ubicamos el script de Python empleado para interactuar con la vulnerabilidad.

Respuesta: /tmp/.X11-unix/X2.py

Tarea 6

Pregunta: What is the CVE ID of the exploited service or daemon that allowed privilege escalation?

Identificamos la vulnerabilidad exacta asociada al demonio de red explotado para la elevación de privilegios.

Respuesta: CVE-2026-24061

Tarea 7

Pregunta: What is the full command the attacker executed to gain higher privileges?

A partir del análisis del historial de comandos, vemos la ejecución del script auxiliar junto con los parámetros locales hacia el servicio.

Respuesta: python3 X2.py 127.0.0.1

Tarea 8

Pregunta: When did the attacker launch the script to exploit the vulnerability to gain higher privileges?

Consultando el archivo de línea temporal (bodyfile.txt) y realizando la conversión de marcas de tiempo Epoch, determinamos el momento exacto del lanzamiento del exploit.

Respuesta: 2026-04-07 17:06:15

Tarea 9

Pregunta: When did the attacker obtain a root shell on the system?

Correlacionando los registros de autenticación (auth.log), identificamos el momento en que se consumó la sesión con privilegios de superusuario.

Respuesta: 2026-04-07 17:06:27

Tarea 10

Pregunta: Once the attacker gained root access on the system, they began preparing for data exfiltration. Data was staged and compressed before being exfiltrated outside the network. What is the full path of the archive file?

Inspeccionando la base de datos de metadatos Tracker3 (meta.db) del usuario y los directorios home, localizamos el archivo comprimido generado para el staging de los datos.

Respuesta: /home/irek/system_logs.zip

Tarea 11

Pregunta: The developer had many sensitive files on their server, including sensitive project files. How many total files were exfiltrated by the attacker and should be considered leaked?

Analizando la cronología de accesos en el bodyfile.txt para el directorio de proyectos del usuario durante la ventana de actividad maliciosa, obtenemos el recuento total de archivos afectados.

Respuesta: 489

Tarea 12

Pregunta: The attacker used a native tool to exfiltrate data from the server. When did the attacker start exfiltrating the archived data?

Tras revisar los registros de comandos y la traza temporal de accesos en el bodyfile (atime correspondiente a la lectura masiva previa a la exfiltración con herramientas nativas como curl), obtenemos la marca temporal exacta.

Respuesta: 2026-04-07 17:11:43

Tarea 13

Pregunta: The attacker used a malicious ELF binary for persistence. What was the path where it was stored on disk before being moved to a new location?

Identificamos la ubicación original del binario ELF malicioso utilizado para asegurar el acceso a largo plazo antes de su reubicación.

Respuesta: /home/irek/les

Tarea 14

Pregunta: After exfiltrating the sensitive data, the attacker set up a stealth persistence mechanism to maintain long-term access on the system. The attacker modified a file to create a stealth persistence workflow that executes the malicious ELF binary whenever a certain activity occurs on the server. What is the full command configured to run the persistence routine?

Inspeccionando los archivos de configuración modificados, identificamos el comando exacto configurado para ejecutar el binario en segundo plano de forma sigilosa.

Respuesta: bash -c 'nohup /usr/bin/les > /dev/null 2>&1 &'

Tarea 15

Pregunta: After setting up the persistence configuration file, the attacker modified the binary responsible for establishing the C2 connection to run with root privileges. When did they perform this action?

Consultando los metadatos del archivo en el bodyfile.txt (específicamente el CTIME, que registra el cambio de permisos y metadatos del binario /usr/bin/les), determinamos el momento exacto de la acción.

Respuesta: 2026-04-07 17:18:24

Conclusiones

El análisis del reto Yggdrasil evidencia un ataque dirigido sofisticado que abarca desde la ejecución de código inicial camuflado en dependencias de desarrollo, la explotación de un demonio local vulnerable para la escalada a root (telnetd), el acopio y exfiltración masiva de 489 archivos de proyectos, hasta el establecimiento de persistencia sigilosa a nivel de sistema.
